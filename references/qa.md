# 出图验收

实现：`scripts/stylebook/qa/`。判定由脚本做，模型只负责「如实转述看到了什么」。

看图验收对照的是本次清单，不会自行补读整篇文章。文章来源即使只出一张，也先用 `planning.md` 对照全文定位置与信息价值；把不能丢的题材事实写入 `points`，尤其是人物场景。漏写在清单里的事实，单张 `qa` 无法凭空发现。

## 六道检查

1. **像素（确定性）**：平均明度、暗部占比、留白、平均饱和度，对照合同 `qa.pixel` 阈值。阈值要用真实出图回测后再定（例：一种暖白黏土样式的阈值用 69 张已发布的真实配图回测，全部通过）。非透明画面另检查原图的透明像素，哪怕只有 1 个也拒绝；显式透明格式保留透明通道。正式批量与单张 `qa --format sticker-single` 均检查 512×512 RGBA、可见主体、四边至少 10% 透明留白和唯一主体连通块；`sticker-grid` 至少要有完全透明背景和清晰可见的主体，宫格切片仍需另走 `sticker-split`。导出非透明格式时同样先检查源图，不能直接把 RGBA 转成 RGB 掩盖边角异常。
   暖色纸底样式可选 `qa.paper_margin_min`，预检黑色墨线和明显色块距画布四边的比例；空图直接拒绝。同一样式的无字场景与有字卡片需要不同纸边时，可在 `qa.paper_margin_min_by_text_mode` 为 `none`、`native`、`overlay` 或 `hybrid` 单独设阈值，未列的模式沿用通用阈值。它只检查可检测的标记，浅色细节、画面是否真正疏朗及手机尺寸可读性仍须看图。不要把全页明亮像素占比等同于四周纸边，也不要未经真实样图回测设定全页留白下限。
2. **独立看图**：默认每张图起一个全新的 `claude -p` 无头进程（默认模型 `claude-sonnet-5`，可用 `STYLEBOOK_QA_MODEL` 改）。也可设 `STYLEBOOK_QA_BACKEND=ark_agent_plan`，用现有 `ARK_AGENT_PLAN_BASE_URL` / `ARK_AGENT_PLAN_API_KEY` 通过豆包视觉模型作一次无历史上下文的独立请求；此路只认 Agent Plan 套餐地址，不回退按量平台。两路都逐条回答合同的「必须看到 / 不许看到」，并把图里所有文字**逐字抄录**；要求缩略或居中方形裁切验收时，Ark 请求会同时传大图与对应的实际导出预览。某条在本图确实不适用可以答 `applicable=false`，但不适用超过三分之一就交人复核。漏答的条目会被点名重问一次，仍漏答按不合格处理。
3. **文字逐字比对**：拿抄录和应有文字比对，缺字、错字、多写都算不合格。原生出字档忽略标点与空白；位图叠字档逐条精确比对（只忽略每条首尾空白，命令内部的空格、连字符和斜杠都必须正确）。本不该有字的图出现了字也算不合格。
4. **内容事实**：批量执行时把配图清单的 `subject`、`relations`、`inventory`、`points` 和 `panels` 交给看图员；单张 `qa` 加 `--manifest 清单.json` 时做同样核对。`points` 按序逐条回答，条件、否定、数字或单位缺失时该条失败，不能只用总体 `content_match` 放行。`comic-4panel` 在计划、编译及带清单的单张验收入口，先检查恰有 4 格非空 `panels` 和非空 `relations`；缺项直接拒绝。同一关键物件跨格延续时，在 `relations` 或后格 `panels` 明写身份与状态：例如第 4 格吃的是第 3 格同一只塌陷、无装饰的蛋糕，不允许突然换成完整的草莓奶油蛋糕；“照样吃”之类的暗示不足以可靠验收。四格等分镜必须按从左到右、从上到下逐格回答，漏格或某格与要求冲突即不合格。无字画面不要求证明精确地名，但可见的地域、时代、动作线索必须相容；不能拿后续路线图替某格补足画面。画风与文字全过，但故事事实不符或结论缺失，整张仍不合格；`deliverables.json` 的 `ready` 保持 `false`。旧版缺少逐条或逐格结论的缓存会在续跑时重新看图，不重出原图。维护者自检与独立复核分别记录，不互相冒充。
5. **实际缩略尺寸**：`wechat-cover-square` 在批量或单张 `qa --format wechat-cover-square` 时，从导出图生成 46×46 的 `*.thumb-46.png`，看图员必须读取这张预览并单独回答主体与主题能否辨认。只有大图合格、缩略后成了小色点时仍拒绝交付。旧版只有大图结论的批量缓存会重看，不重出图；缩略图是验收过程件，不是交付图。
6. **居中方形裁切**：`wechat-cover-head`、`xhs-cover`、`xhs-carousel` 的最终导出图另取实际居中方形。看图员必须读取方形图，单独回答标题、主体、题目要求的图形标记和承载信息的次要元素是否完整、与边缘是否有余量；被截断或贴边看不完整即不合格。批量缓存缺少 `square_crop` 结论时重看图，不重生图；单张 `qa --format` 生成 `*.qa-square.png` 后检查。
   S02@r3 另设 `qa.center_square_margin_min: 0.15`：正式 `qa` 对实际居中方图的高对比内容量测四边留白，低于阈值即拒绝，即使看图员主观判「有余量」也不能放行。此量测只适用于该深底样式，不能替代文字、内容和画风看图。

技术分栏里同一主体的正侧背面或局部辅助视图按同一身份计数；出现不同身份的额外人物仍须拒收。人物自身的左／右不按观者的画面左／右替代；看不清方向时报告无法核实。该说明只澄清看图口径，不改变题目的主体、数量或空间关系要求。

合同里 `qa.when_text` 列出的条目只在图里有字时检查（例如「标题是黏土字」对无字的人物图不适用）。
英文 ghost 层的“不得大于主标题”按字高和视觉权重判断，不按整行宽度；低不透明度的白字在深底上看起来会是灰色。真正字高过大、对比抢过中文标题或缩略图先看到英文时仍拒收。这沿用写作技能原配方的字高定义，不改私有 S02 合同与来源逐字对照。

## 命令

```bash
python3 scripts/sb.py qa 图.png --style C31 --text "番茄工作法|专注25分钟" --format xhs-carousel --report 报告.json
python3 scripts/sb.py qa 图.png --style C31 --manifest 本张图的清单.json --report 报告.json
python3 scripts/sb.py sheet 定妆图.png 图2.png 图3.png -o 对照.png     # 一致性对照网格
python3 scripts/sb.py sheet 封面.png --thumbs -o 缩略.png               # 46/66/128 像素可辨认
python3 scripts/sb.py qa-contrast 问题图.png 候选图.png --defect-file 禁止特征.txt --report 对照.json
```

退出码 1 = 不合格，输出里的 `problems` 就是返修依据。
单张验收若没有清单，只检画风、像素和明确给出的文字；手工结论里若提供了 `content_match`，它同样必须有效且为真。需要证明画面符合原题时传 `--manifest`，不能用未核内容事实的绿灯充作整张图合格。

叠字版式可在合同的 `qa.overlay_layout` 填 `headline_min_font_px_ratio` 和／或 `subtitle_max_lines`。正式单张验收须带清单；批量验收会传入同一清单。前者只用叠字字号相对最终画布高度排除明显过小的标题，后者按换行符限制副标题行数。两项都是必要条件，仍要实际看图核对字高、层级与方图裁切。S02 的旧切图重排试稿曾在 383 px 高封面使用 36 px 标题及双行副标题，居中方图边距合格却不符合同；该试稿不可用作准入证据。

## 边界缺陷的双图对照

逐张看图都判绿、但维护者看到明确材质或构图差异时，先把**一个可观察的禁止特征**写进 UTF-8 `禁止特征.txt`，用 `qa-contrast --defect-file` 比较已知问题图与返修候选。`--criterion-file` 则只接受希望画面满足的正向特征；两种写法的缺陷真假方向相反，不可混用。两次请求不透露哪个是旧图，并交换 A/B 顺序；只有两次都指出旧图有该缺陷、候选没有且选候选时，才返回 `candidate_better`。位置偏好、两张都过、两张都不过或结论分歧均为 `inconclusive`，退出码 1。报告含原图 SHA-256 和两次原始回答；已有报告不会被覆盖。此入口当前只走已配置的 Ark Agent Plan 独立看图套餐。

如果缺陷只在局部，先用**相同像素区域**裁两张图，再把裁图送入对照；同时保留全图与裁图，记录裁切框。2026-09-27 C58 雨后石路诊断中，全图对照因一轮把候选看成过干而给 `inconclusive`，同框路面裁图两次换序才稳定指出旧图亮面过多。裁图对照只能说明该局部相对改善，仍须对最终全图做内容、画风、文字、像素验收；不能把 `candidate_better` 写成正式样式准入。

整图逐条验收也可能漏掉局部材质缺陷。遇到已知反例仍被整图判绿时，可把**同一条可观察判据**分别用于反例区域和候选区域的独立裁图看图；先确认已知反例被拒，再确认候选通过，保存原图、裁切框、判据和原始回答。2026-09-27 C58 的两张镜面湿路裁图在这一步均被拒，返修后的哑光路面裁图通过；对应整图此前有漏判。此检查只补足局部诊断，裁切可能隐藏主体、文字和空间关系，整图仍须另行验收。同一判据若在其他已知反例上漏判，不得升为自动硬闸或据此准入样式。

维护者可对**已裁好的局部图**运行 `python3 scripts/sb.py qa-focus 局部.png --original 整图.png --criterion-file 判据.txt --report 局部复核.json`。命令对同一局部做两次无历史上下文的独立看图；两次都明确回答禁止特征不存在才返回 0，任何出现、漏答或分歧返回 1。报告保存局部与整图哈希及原始回答，已有报告不覆盖。裁图须保留裁切框和原图，先用同一判据跑已知反例，确保它返回 1，再检查候选。`qa-focus` 只检查局部缺陷，不检查整图内容、文字、像素与风格矩阵。

## 没有可用独立看图入口的宿主（Codex 等）

用 manual 模式：宿主模型按 `stylebook.qa.review_prompt(...)` 生成的问题自己看图，写出同样结构的 JSON，再用 `--review-json 结论.json` 交给脚本判定。
`must_see` 每条须有布尔 `ok` 与非空 `why`，`must_not_see` 每条须有布尔 `present` 与非空 `why`；即使图里没有文字，也要写 `"transcribed_text": []`。缺字段、重复条目或无依据的结论会被拒绝，不能把未知当作「未出现」。

若 Claude CLI 未登录或订阅访问被拒，或 Ark Agent Plan 的地址、Key、额度不可用，批量独立看图会在首张对应错误后停下，保留已出的图片与结论。此时可用 manual 模式继续单图自检；维护者自行看图的记录不能充作准入所需的两次独立复核。

批量输出的 `deliverables.json` 和 `report.md` 记录每张图的 `review_source`。默认 Claude CLI 标为 `claude_cli`，选 Agent Plan 标为 `ark_agent_plan`；注入其他看图结果时由调用者标明来源，未标明则为 `provided_unspecified`；历史缓存缺来源标为 `legacy_unknown`。`ready: true` 只表示该来源下的检查已通过，不能单独证明独立复核或样式准入。续跑沿用缓存结论时保留原来源，不用本次传入的来源覆盖。

## 返修

`overlay` / `hybrid` 的底图可能要求「无字、留白」，最终成图则应有准确文字。若 `content.relations` 写了只适用于底图的指令，在清单另写 `content.final_relations` 描述成图的实际空间关系；生图仍用 `relations`，成品质检用 `final_relations`，而 `subject`、全部 `points` 和逐字文字要求照常检查。`final_relations` 不得省略必要事实或拿来豁免内容错误。

按 `problems` 逐条改清单（改内容描述、加硬约束、换参考图），**只重出这一张**；同一张最多重试 2 次，仍不合格就把图与原因交给用户，不无限重抽。

## 已知局限

同一张图两次独立看图，结论可能不同（2026-09-25 实测：同一张黏土风格的 T8 一次判过、一次判不过，分歧在「玉绿只作点缀」这类程度判断）。准入这类高影响判定要看两次，不一致交人复核。
